# Gold Inventory Dashboard

Turns our gold purchase records into a 3-page site: a home page with the
national profit/loss summary, a full sortable/searchable inventory table,
and a page comparing today's Tanishq (national) rate against four
Kolkata-specific sources. All three pages are self-contained HTML files
(nav bar links between them) you can open directly in a browser.

## The five scripts

| Script | What it does |
|---|---|
| `fetch_tanishq_gold_rate.py` | Scrapes today's 22 Karat (1 gram) gold rate from Tanishq's public rate page using a stealth-configured headless Chromium (Playwright), since the site sits behind Cloudflare. Saves it to `fetch_tanishq_gold_rate.json`. If every attempt fails, it falls back to the last known rate instead of failing the pipeline (see "Stale rate fallback" below). |
| `fetch_excel_data.py` | Logs into Microsoft Graph API with an Azure app registration (service-account credentials, no human login) and downloads the `Gold Inventory.xlsx` file from SharePoint. Saves the rows as `fetch_excel_data.json`. |
| `compair_to_other_rate.py` | Fetches today's 22K rate from Tanishq plus four Kolkata-specific sources (ABP Live, Times of India, Goodreturns, GoldPriceIndia) via headless Chromium, and saves them to `compair_to_other_rate.json`. Any source whose live fetch fails falls back to its own last known rate (marked stale in its `note`) instead of just vanishing from the comparison - see "Stale rate fallback" below. |
| `build_gold_all_ditails_with_table.py` | Reads the Tanishq rate + inventory JSON files, computes "Our Amount" / "Today's Value" / "Profit-Loss" per item and in total, and writes the full inventory table to `gold_all_ditails_with_table.html`. |
| `build_gold_asset_value_matching.py` | Reads the same two JSON files as above and writes the home page (`Gold_asset_value_matching.html`): a "National calculation" summary (available gold, today's rate, total value) plus an empty "Kolkata calculation" section reserved for future work. |

`compair_to_other_rate.html` itself isn't generated by a script - it's a
static page that fetches `compair_to_other_rate.json` live in the browser
(with an embedded fallback snapshot for when it's opened directly via
`file://`, where a live `fetch()` can't work).

## Running it locally

**One-time setup:**

```
pip install -r requirements.txt
python -m playwright install chromium
```

Copy `.env.example` to `.env` and fill in real values (see "Environment
variables" below) - only needed for `fetch_excel_data.py`.

**To regenerate the site, run the scripts in this order:**

```
python fetch_tanishq_gold_rate.py
python fetch_excel_data.py
python compair_to_other_rate.py
python build_gold_all_ditails_with_table.py
python build_gold_asset_value_matching.py
```

Then open `Gold_asset_value_matching.html` (the home page) in a browser.

## Automation (GitHub Actions)

`.github/workflows/update-dashboard.yml` runs all five scripts
automatically every day at 08:00 IST (`cron: "30 2 * * *"` UTC), or
on-demand via the workflow's "Run workflow" button. A failed
`compair_to_other_rate.py` run doesn't stop the rest of the pipeline
(the main dashboard doesn't depend on it, and it has its own per-source
stale fallback) - the other two fetch steps still block the build steps on
failure, same as before. If the data files or generated HTML changed, it
commits and pushes them back to `main` as `github-actions[bot]`, then
deploys all three HTML pages to GitHub Pages, plus `compair_to_other_rate.json`
(needed for that page's live fetch to work once hosted). The other two JSON
files stay off the published site since they contain vendor names and
purchase rates.

Live Pages URL: `https://debnathaiincorg.github.io/Gold-asset-value-matching/`
(serves `Gold_asset_value_matching.html`, the home page) - confirmed live
and up to date with each automated run as of 2026-08-03.

## Environment variables

`fetch_excel_data.py` needs three Azure app-registration values, loaded
from a local `.env` file (see `.env.example` for the exact variable
names - never commit the real `.env`, it's already gitignored):

- `AZURE_TENANT_ID`
- `AZURE_CLIENT_ID`
- `AZURE_CLIENT_SECRET`

In GitHub Actions, the same three values come from repository secrets
(Settings → Secrets and variables → Actions) instead of a `.env` file -
see the `env:` block on the "Fetch gold inventory from SharePoint" step
in the workflow.

## Stale rate fallback

`fetch_tanishq_gold_rate.py` and `compair_to_other_rate.py` both scrape
public webpages, not an official API, so a fetch can occasionally fail
(Cloudflare challenge, page redesign, network blip). Rather than letting
that take down the whole daily pipeline, each falls back to the last
successfully-fetched value instead of failing or dropping the data point:

- `fetch_tanishq_gold_rate.py` reuses the last successful rate already
  sitting in `fetch_tanishq_gold_rate.json` and marks it `"is_stale": true`
  with a `"stale_reason"`. A successful fresh fetch always writes
  `"is_stale": false`.
- `compair_to_other_rate.py` does the same per source (any of its 5 rate
  sources can fail independently) - a source that fails this run falls
  back to its last known rate from `compair_to_other_rate.json`, with its
  `"note"` field flagging it as stale, instead of vanishing from the
  comparison entirely. A source is only left out if it has never once
  succeeded.

## Dashboard notes

- Only the **Date** column is sortable (click the header to toggle
  ascending/descending); this is by design - the other columns are
  display-only.
- The search box and "Hide sold items" checkbox filter the table live,
  and the summary cards above it recalculate from whatever rows are
  currently visible.
